# Basic Memory 知识库笔记规范

知识库 = Basic Memory project `main`。根下只有三个顶层目录：

| 目录 | 放什么 |
| --- | --- |
| `projects/<project>/<function>/` | 只影响一个项目的知识 |
| `reference/<discipline>/` | 跨项目通用的知识，按学科分组 |
| `inbox/` | 还没想清楚放哪的，先扔进来，之后再分拣 |

## 先判断：该不该写

写之前先过三关，任何一关过不了就别写：

1. 这条内容对**以后**的某个任务还有用吗？只是本次对话的过程记录，不写。
2. 已经有笔记覆盖它了吗？有就补充那一条，不要再建一条重复的。
3. 它是代码仓库自己的文档吗？README、API 设计、变更日志留在仓库里，不复制进知识库。

拿不准某条内容该不该进知识库时，先问用户，不要默认复制。

## 一条笔记 = 一个主题

- 文件名用稳定、可读的**中文**主题名。Obsidian 靠文件名解析 `[[wiki-link]]`，所以 `[[Basic Memory 底层模型 × 运行时选型]]` 直接指向中文文件。
- permalink 允许用英文 slug，它是稳定引用和 URL，**不是** wiki-link 的目标。不要为了 permalink 把文件改成英文名。
- 一条笔记只讲一件事；跨学科的内容拆成原子笔记，再用 wiki-link 连起来。

## 标签是检索过滤器，不是描述

- 每条笔记：1 个主场标签（必填）+ 0–2 个检索标签，总数 ≤ 3。
- 小写英文；`/` 表示层级，层级 ≤ 2。
- 一个概念只留一种拼写；同义词合并，没人用的标签删掉。
- 不要用 `knowledge`、`important` 这类宽泛标签。

## 关系用 wiki-link，不用标签

- 关联关系一律写成 `[[note]]`，不要把关系塞进标签。
- 链接名用目标笔记的文件名或稳定标题。
- 项目笔记引用通用知识时，链到 `reference/` 下的笔记；一条项目笔记可以连多篇通用笔记。

## 移动、提升、归档

- 移动或重命名用 `bm_move`，保持 permalink 稳定，移动后检查断链。
- 一条项目笔记被**第二个项目**引用后，从 `projects/` 提升到 `reference/`。
- 删除前先归档。目录移动很便宜，标签和链接才是真正的结构。

## 写之前的检查单

- 这条笔记只表达一个主题吗？
- 它属于 `projects/`、`reference/` 还是 `inbox/`？
- 文件名是中文且稳定吗？
- 有且只有 1 个主场标签、最多再 2 个检索标签吗？
- 关系是用 wiki-link 表达的，不是标签？
- permalink 稳定吗？需要英文 slug 吗？
